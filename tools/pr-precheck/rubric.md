# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Diff matches the plan | Compare every changed file and material diff hunk with the accepted plan's scope, files, exclusions, and `## Deviations`; compare the PR description's change and limitation claims with that diff. | Pass when every material change is planned or explicitly recorded with a reason in `## Deviations`, every remaining promised change is present, and the description accurately states what the diff does and leaves out. An honestly recorded narrower outcome passes when the updated plan and description make the boundary explicit. Unrecorded extra work, an omitted promised change, or a description contradicted by the diff fails. | required |
| Issue behavior is decisively tested | Compare the test evidence with the reproduction trigger, expected result, controls, and the current plan's test plan. | Pass when the evidence exercises every distinct issue behavior still claimed by the current plan through the affected path and shows an observable before/after or equivalent red/green result that distinguishes the fix from the reproduced failure. A representative regression test may cover equivalent callers changed by the same mechanism, and a focused automated assertion may prove a supporting invariant. Named controls may remain unchanged. Generic assurances, evidence for an unchanged path, or omission of a distinct claimed failure mode fails. | required |
| Repository checks are reported | Read the test-evidence commands and outcomes against the repository's required executable checks and the plan's broader verification commands. Read checklist-only standards under the repository-standards check instead. | Pass when every applicable executable check is named and has an unambiguous outcome. A concise result such as a pass count or `passes` is evidence; a full transcript is not required. An expected `no tests ran` or an honestly disclosed failure may pass when the command was run and the result does not contradict the fix. A missing executable check, an unstated outcome, or an admission that it was not run fails. | required |
| Diff is reviewable | Inspect the unified diff and commit list for the intended fix, unrelated hunks, debugging remnants, dead or commented-out attempts, broad formatting churn, generated debris, and temporary instrumentation. | Pass when a reviewer can attribute every material hunk to the bounded change or its focused verification and the submitted diff contains no leftover investigation debris. A correct fix buried with unrelated cleanup, debug output, dead code, commented-out attempts, or avoidable churn fails even when tests pass. | required |
| Repository standards are satisfied | Compare the title and description with the repo-facts or live PR template, contribution guide, issue-linking rules, required checklist and documentation artifacts, applicable disclosure policy, and explicit maintainer direction. | Pass when the title is specific, every applicable template section has truthful content, the issue is linked as required, required checklist or documentation artifacts are present, applicable disclosure requirements are met, and explicit maintainer direction is addressed. A checklist attestation satisfies a non-executable hygiene item such as formatting unless the diff contradicts it; ordinary competing work need not be discussed unless the repository or a maintainer asks. Honest unchecked items are allowed when the template permits them and their status is explained. Missing required sections, boilerplate, absent required artifacts, or an unmet stated disclosure rule fails. | required |

## Verdict rule

Accept only when every required check passes. Reject when any required check fails or is unclear. Preferred checks, if added later, may appear in the summary but never change the verdict.
